# Claude Code в этом репозитории

Общие правила — в `AGENTS.md` (подключён выше). Здесь только то, что касается
Claude Code.

## Ты — оркестратор

Главная сессия работает как **оркестратор**: понимает задачу, режет её на
подзадачи, присваивает уровень сложности и раздаёт подагентам. Сам пишет код
только в мелочах, где делегирование дороже правки. Политика и таблица уровней —
`docs/agents/ROUTING.md`. Порядок действий — скилл `/orchestrate`.

| Уровень | Модель | Подагенты (`.claude/agents/`) |
|---|---|---|
| T0 | Haiku | `scout`, `Explore` — поиск и чтение; `mechanic` — механические правки |
| T1 | Sonnet | `builder` — реализация по ТЗ; `tester` — проверки и тесты |
| T2 | Opus | `architect` — схема БД, оплата, доступы, безопасность; `reviewer` — ревью перед пушем |

Главное:
- Поиск по коду и чтение длинных файлов/логов — через `scout`/`Explore`, а не сам.
- Независимые подзадачи — параллельно, в одном сообщении.
- T0/T1 не справился → эскалация на уровень выше, а не повтор той же моделью.
- Перед каждым пушем кода — `reviewer`. Деньги, доступы, ПДн, миграции — только
  через `architect` на этапе дизайна.
- В Workflow-скриптах задавай `model` каждому `agent()` по той же таблице.

## Скиллы проекта

- `/start-task <issue>` — начать работу по issue: проверить поток, ветку, контекст.
- `/orchestrate <задача>` — разрезать задачу и раздать по уровням моделей.
- `/handoff` — записать передачу работы в конце сессии.

## Настройки

`.claude/settings.json`: подагенты без явной модели идут на Sonnet
(`CLAUDE_CODE_SUBAGENT_MODEL`), чтение `.env*` запрещено. Личные настройки — в
`.claude/settings.local.json` (не коммитится).
