# Оркестратор и маршрутизация моделей

Цель — тратить лимиты старших моделей только там, где они дают качество, а
всю рутину отдавать младшим, **не теряя качества результата**.

## Схема

```
Владелец (задача / issue)
        │
        ▼
Оркестратор = главная сессия (Opus)
  • понимает задачу, режет на подзадачи, присваивает уровень T0/T1/T2
  • раздаёт подзадачи подагентам, сам код почти не пишет
  • собирает результат, проверяет, коммитит, пушит, ведёт PR
        │
        ├── T0 · Haiku  ── scout, Explore (поиск, чтение), mechanic (механические правки)
        ├── T1 · Sonnet ── builder (реализация по ТЗ), tester (проверки и тесты)
        └── T2 · Opus   ── architect (решения с высокой ценой ошибки), reviewer (ревью перед пушем)
```

Подагенты лежат в `.claude/agents/`, модель зашита в их frontmatter (`model:`),
поэтому выбор модели не зависит от памяти оркестратора. Проектный
`.claude/settings.json` ставит `CLAUDE_CODE_SUBAGENT_MODEL=sonnet`: любой
подагент без явной модели (general-purpose, агенты workflow) идёт на Sonnet, а
не наследует Opus.

> **Нужен Claude Code v2.1.251 или новее.** Порядок выбора модели подагента:
> параметр `model` при вызове → `model:` во frontmatter →
> `CLAUDE_CODE_SUBAGENT_MODEL` → модель главной сессии. До v2.1.251 переменная
> стояла первой и перебивала frontmatter — тогда и `reviewer`, и `scout` ушли бы
> на Sonnet. Проверить версию: `claude --version`, обновить: `claude update`.
> `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` не ставить — он отключает маршрутизацию.
>
> Встроенный `Explore` по умолчанию работает на модели главной сессии (Opus),
> поэтому в проекте он переопределён файлом `.claude/agents/Explore.md` с
> `model: haiku`.

## Как выбрать уровень

| Уровень | Модель | Подагенты | Когда | Примеры в этом проекте |
|---|---|---|---|---|
| **T0** | Haiku, effort low | `scout`, `Explore`, `mechanic` | Ответ однозначен, суждение не нужно. Ошибку видно сразу и она дешёвая. Не касается чувствительных зон (вопрос 1 ниже). | Найти, где проверяется доступ к уроку (найти, а не менять). Пересказать лог CI. Переименовать UI-компонент. Добавить ключи локализации по готовому списку. |
| **T1** | Sonnet, effort medium | `builder`, `tester` | Понятное ТЗ, один модуль, есть образец в коде. Ошибку ловят тесты и ревью. | Страница каталога курсов. Блоки урока в редакторе. Квиз по описанной логике. Починить тест с известной причиной. |
| **T2→T1** | дизайн и ревью — Opus, реализация — Sonnet | `architect` → `builder` → `reviewer` | Чувствительная зона, но после дизайна реализация типовая. | Назначения курсов (создают доступ). Отчёт и выгрузка CSV (ПДн, изоляция компаний). Загрузка файлов. Страница проверки сертификата (ФИО публично). Открытие уроков по расписанию. Согласие на обработку ПДн. |
| **T2** | Opus, effort high | `architect`, `reviewer` | Цена ошибки высокая или требования неясны. Решение трудно откатить. | Схема БД и миграции. Оплата, вебхуки, возвраты. Проверка доступа. Авторизация и роли. Компании-клиенты. Выбор сервисов. Баг, который T1 не победил. |

Как выбрать — вопросы **строго по порядку**, первый «да» решает:
1. **Затрагивает деньги, доступы и авторизацию, ПДн, схему БД и миграции,
   загрузку файлов, безопасность — или неясно, как делать?** Да → **T2** (если
   после дизайна реализация типовая — **T2→T1**). Даже если правка «механическая».
2. **Нужно только найти, прочитать или механически поправить по точной
   инструкции?** Да → **T0**.
3. **Есть ТЗ и образец в коде, ошибку поймают тесты?** Да → **T1**.
4. Ничего не подошло или сомневаешься → уровень **выше**.

## Правила качества (без них экономия запрещена)

1. **Ревью не экономим.** Любой дифф с кодом перед пушем проходит `reviewer`
   (Opus). Диффы в `docs/**`, `DECISIONS.md`, `AGENTS.md`, `CLAUDE.md` и
   `.claude/**` тоже проходят `reviewer` — с упором на утечки в публичный
   репозиторий, противоречия между документами и права агентов. Без ревью
   можно пушить только опечатки и отметки занятости.
2. **Деньги и доступы — только T2** на этапе проектирования и ревью.
   Реализацию по утверждённому дизайну может делать `builder`.
3. **Эскалация вверх, не повтор.** T0 отказался или T1 дважды не справился —
   переводим задачу на уровень выше с описанием, что пробовали. Не гоняем
   ту же модель третий раз.
4. **Проверяемость.** Результат T0/T1 принимается, только если его можно проверить:
   тесты, typecheck, lint, сверка с ТЗ. Нечем проверить — уровень выше.
5. **Контекст режем, а не копируем.** В промпт подагенту — цель, пути к файлам,
   критерий готовности. Не вставлять целые файлы и логи: подагент прочитает сам.
6. **Параллелим независимое.** Несколько T0/T1 задач без общих файлов —
   запускать одновременно (в одном сообщении). Правки одних и тех же файлов —
   последовательно или в отдельных worktree.

## Шаблон поручения подагенту

```
Цель: <одно предложение, что должно получиться>
Контекст: <issue #N, раздел SPEC, ключевые пути>
Границы: <какие папки можно менять, что нельзя трогать>
Готово, когда: <проверяемый критерий: тест X зелёный / страница Y открывается / …>
Верни: <список файлов + краткий итог / найденные факты / вопрос на эскалацию>
```

## Метки в GitHub

У каждой задачи есть метка уровня. По ней оркестратор (или человек) сразу
видит, кому её отдавать:

- `tier:T0` — Haiku: поиск, механика, документация по фактам.
- `tier:T1` — Sonnet: реализация по ТЗ, тесты.
- `tier:T2→T1` — дизайн и ревью на Opus, реализация на Sonnet.
- `tier:T2` — Opus: архитектура, деньги, доступы, безопасность, решения.

Метку ставит тот, кто заводит задачу, по вопросам выше (форма issue не умеет
ставить метки из выпадающего списка — ставим руками сразу после создания).
Сомневаешься — ставь уровень выше.

## Workflow-скрипты

В скриптах Workflow модель задаётся на каждый вызов:
`agent(prompt, { model: 'haiku' | 'sonnet' | 'opus', effort: 'low' | 'medium' | 'high' })`.
Правило то же: сбор и поиск — `haiku`, реализация — `sonnet`, проверка и судья —
`opus`. Если модель не указана, срабатывает `CLAUDE_CODE_SUBAGENT_MODEL` (Sonnet).

## Данные в ИИ-сессиях

Claude — зарубежный ИИ-сервис. В сессию (промпты, логи, файлы для разбора) не
передаём персональные данные с прода: только обезличенные выборки и
синтетические тестовые данные (D-009). Логи с прода — сначала замаскировать
email, телефоны, ФИО, БИН/ИИН.

## Если нужно ещё экономнее

- Главную сессию можно запускать с `/model opusplan`: Opus в режиме плана,
  Sonnet при исполнении. Подходит для задач, где план важнее кода.
- `/effort` у главной сессии снижать на рутинных днях (правки текстов, мелкие баги).
