---
name: handoff
description: Записать передачу работы в конце сессии (или перед долгой паузой) в docs/handoffs/, чтобы следующая сессия продолжила без потерь и не пересеклась с другими. Вызывается пользователем командой /handoff (коммитит, пушит и пишет в issues).
disable-model-invocation: true
---

Создай `docs/handoffs/YYYY-MM-DD-<поток>-<тема>.md` (дата — сегодня) по шаблону:

```
# <тема> — передача работы
Дата: YYYY-MM-DD · Поток: <stream> · Ветка: <ветка> · Issues: #N, #M

## Сделано
- <что именно, со ссылками на коммиты/PR>

## Не доделано
- <что осталось, где остановились, что уже пробовали>

## Ждёт решения владельца
- <вопрос> — рекомендую: <вариант> (почему)

## Как продолжить
1. <первый шаг следующей сессии>

## Подсказка для следующей сессии
<готовый промпт одним абзацем: «Продолжи … в crp-kz, ветка …, прочитай …»>
```

Затем:
- освободи свою зону в `docs/WORKSTREAMS.md`, если работа закончена;
- прогони `reviewer` на эти файлы (утечки, ПДн, коммерческие условия);
- оформи их отдельным маленьким PR в `main` с коммитом `docs(handoff): …`,
  чтобы его влили сразу (`main` ещё нет — в базовую ветку из `AGENTS.md`);
- в каждом затронутом issue оставь комментарий: краткое содержание handoff и
  ссылка на PR. Комментарий виден другим сессиям сразу, файл — после мержа.

Никаких секретов, ПДн и коммерческих условий в handoff — репозиторий публичный.
