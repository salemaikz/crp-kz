description: Начать работу по issue в crp-kz — проверить, не занята ли задача, подтянуть контекст, отметиться в issue. Вызывается пользователем командой /start-task.
argument-hint: "<номер issue>"
disable-model-invocation: true
---

1. Открой issue #$ARGUMENTS (GitHub MCP). Прочитай описание, метки
   (`stream:*`, `tier:*`, `phase:*`) и комментарии. Если кто-то назначен или
   написал «взял» и ветка жива — остановись и сообщи пользователю.
2. Прочитай `docs/WORKSTREAMS.md`. Задача в зоне, которую кто-то занял (в файле
   или по назначенным issues)? Остановись и скажи, с кем пересечение.
3. Найди последний handoff потока в `docs/handoffs/` и в комментариях issue.
4. Ветка: **оставайся на выданной сессии ветке** (облачные сессии — `claude/*`).
   Подтяни базу: `git fetch origin main && git merge origin/main` (пока `main`
   нет — базовая ветка указана в `AGENTS.md`). Локально без выданной ветки —
   создай `feat/<поток>-<тема>` от `origin/main`.
5. Назначь себя на issue и оставь комментарий: «Взял. Ветка `<ветка>`.
   План: <3–5 пунктов>».
6. Дальше — `/orchestrate` с этой задачей.
