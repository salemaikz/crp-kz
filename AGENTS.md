# CRP KZ — правила для всех агентов и разработчиков

Платформа обучения **ЦРП — Центра Развития Предпринимателей** (консалтинговая
компания, Астана). Две задачи одной платформы:

1. **Обучение сотрудников ЦРП** — курсы, назначения со сроками, тесты, статистика.
2. **Платные курсы для клиентов ЦРП** — создаём курс, публикуем, после оплаты
   выдаём доступ; позже — места для сотрудников компаний-клиентов (B2B).

Подрядчик и разработчик — SalemAI. Эти правила обязательны для Claude Code,
Codex и людей. Специфика Claude Code — в `CLAUDE.md`.

> **Описательные** документы (карта кода, команды) при расхождении с кодом
> правятся под код. **Нормативные** — `AGENTS.md`, `docs/lms/SPEC.md`, решения
> со статусом «принято» в `DECISIONS.md`, `docs/brand/BRAND.md` — важнее кода:
> расхождение с ними — баг в коде, заводим issue и чиним код.
> Пометка `[дозаполни]` = факт не подтверждён, не считать его истиной.
> Решение со статусом «предложено» = ещё не принято, на него нельзя опираться
> как на факт.

## Источник задач — GitHub

- Любая работа = **issue** в `salemaikz/crp-kz`. Нет issue — сначала заведи
  (шаблон «Задача»), потом делай. Устные договорённости из чатов переносим в
  issue или `DECISIONS.md`, иначе их не существует.
- У issue есть метки: поток (`stream:*`), уровень сложности
  (`tier:T0|T1|T2→T1|T2`, см. `docs/agents/ROUTING.md`), этап (`phase:*`),
  `mvp` — входит в MVP, `owner-decision` — решает владелец.
- Взял задачу — назначь себя/оставь комментарий «взял, ветка `<имя>`».
  Задача без отметки считается свободной.
- Одна задача → одна ветка → один PR. PR ссылается на issue (`Closes #N`).

## Как не пересекаться с другими сессиями

1. **В начале сессии** прочитай `docs/WORKSTREAMS.md`, открытые PR и issues
   своего потока (кто назначен, кто написал «взял»). Последний handoff потока —
   в `docs/handoffs/` и в комментариях issue.
2. **Занятость отмечается в GitHub, а не только в файле:** назначь себя на issue
   и напиши «взял, ветка `<ветка>`». У каждой сессии своя ветка, поэтому правка
   файла в ветке другим не видна, пока PR не влит. Комментарий в issue виден сразу.
3. Меняй файлы **только в зоне своего потока** (папки перечислены в WORKSTREAMS).
   Нужна правка в чужой зоне — заведи issue на владельца зоны, сам не правь.
4. Координационные файлы (`docs/WORKSTREAMS.md`, `docs/handoffs/*`): ревью
   `reviewer` на утечки → отдельный маленький PR в `main`, который вливается
   сразу; краткое содержание — комментарием в issue. Общие файлы с последствиями
   (`AGENTS.md`, `CLAUDE.md`, `DECISIONS.md`, миграции, `package.json`,
   `messages/*.json`) — отдельным коммитом, обычным путём: ревью → PR.
5. **В конце сессии** — handoff: попроси пользователя запустить `/handoff`;
   в автономной сессии выполни шаги из `.claude/skills/handoff/SKILL.md` сам.
6. Работа над CRM ЦРП идёт **в приватном репозитории SalemAI**, а не здесь. Его
   не трогаем (подробности — WORKSTREAMS).

## Git

- `main` — стабильная ветка, напрямую не пушить. Работа — в фича-ветках, слияние
  через PR. Облачные сессии Claude получают ветку `claude/*` автоматически — это ок:
  остаёшься на выданной ветке и подтягиваешь `main` через
  `git fetch origin main && git merge origin/main`.
  `[дозаполни: ветку main создаёт владелец; до этого базовая —
  claude/amazing-pascal-agse3o]`
- Ручные ветки: `feat/<поток>-<тема>`, `fix/<поток>-<тема>`, `docs/<тема>`.
- **Conventional commits**, тема по-русски: `feat(courses): …`, `fix(payments): …`,
  `docs(brand): …`. Скоуп — домен: `courses`, `lessons`, `quiz`, `access`,
  `payments`, `orgs`, `auth`, `certs`, `admin`, `brand`, `agents`, `infra`,
  `lms` (ТЗ и план), `handoff`.
- Тело коммита — *зачем* и компромиссы, а не пересказ диффа.
- Никогда: `--no-verify`, `push --force` в чужую ветку, переписывание истории `main`.

## Стек (как в SalemAI — чтобы код и люди были взаимозаменяемы)

Next.js 16 (App Router, сборка `next build --webpack`, не Turbopack) · React 19 ·
TypeScript strict · Tailwind 4 · PostgreSQL через `postgres` (postgres.js, без ORM;
в camelCase — только имена колонок, jsonb не трогается, строки — обычные объекты) · Zod · Zustand · next-intl · своя session-auth (cookie + bcryptjs,
**без JWT и NextAuth**) · @react-pdf/renderer (сертификаты, счета) · почта: очередь в БД, провайдер — после решения ЦРП (D-030, D-009) ·
тесты: node:test + tsx (unit, интеграционные с БД), Playwright (e2e).

This is NOT the Next.js you know: перед кодом под Next 16 читай гайд в
`node_modules/next/dist/docs/` — API и соглашения изменились.

## Код и данные

- Пользовательский текст — только через локали `messages/{ru,kz}.json`. Строки
  в коде не хардкодить. Тест паритета ключей обязателен.
- Казахский: сегмент URL и имя файла — `kz` (как в SalemAI), но для `Intl`
  (даты, числа, плюрализация), `<html lang>` и `hreflang` — ISO-код **`kk`**
  (D-002). `kz` — код страны, а не языка.
- БД: id — `TEXT` (UUID), время — `BIGINT` epoch-мс, деньги — `BIGINT` в целых
  тенге (`amount_kzt`). Миграции — `migrations/YYYY-MM-DD-<slug>.sql`, строго
  идемпотентные (`IF NOT EXISTS`), только добавляющие (расширение закрытого списка CHECK считается добавляющей правкой, D-037).
- **Доступ к платному контенту проверяется на сервере** в каждом API и на каждой
  странице урока. Клиенту не отдаём правильные ответы квизов и ссылки на закрытое видео.
- Небольшие модули, без мега-файлов. Комментарии в коде — по-русски, по делу.
- Новые функции выходят **за флагом** и в production выключенными, пока не прошли
  приёмку. В демо флаги включены: там владелец функции и принимает (D-025).

## Проверки перед пушем

`npx tsc --noEmit` · `npm run lint` · `npm run test:unit` · интеграционные тесты
затронутого модуля · e2e для пользовательских сценариев (покупка → доступ → урок →
тест → сертификат). Падает — не пушим. Тест нельзя отключать ради зелёного прогона.
Команды уточняются в `package.json` после создания каркаса `[дозаполни]`.

## Безопасность и данные

- **Репозиторий публичный.** Не коммитить: секреты и `.env*`, персональные данные
  сотрудников и клиентов, коммерческие условия и цены договора, внутренние
  цифры продаж ЦРП, IP и доступы серверов. Это хранится вне репозитория у владельца.
- Персональные данные граждан РК храним на сервере в Казахстане (D-009).
  Передача ПДн в зарубежные сервисы (ИИ, почта, видео) — только после решения
  ЦРП и с согласием пользователя.
- **ПДн с прода не передавать в ИИ-сессии** (Claude, Codex и др.): ни в промпты,
  ни в логи и файлы для разбора. Только обезличенные или синтетические данные.
- Платёжные вебхуки: проверка подписи, идемпотентность, повторная доставка не
  выдаёт доступ дважды; возврат платежа отзывает доступ.
